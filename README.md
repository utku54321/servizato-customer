# Servizato

Customer app for the Servizato service marketplace: book a home service, pick a provider and time slot, track the technician live, share the start OTP, pay the invoice and leave a review.

Built with **React Native (Expo SDK 57)** for **Android and iPhone**. It works together with the other two Servizato apps ([customer](https://github.com/utku54321/servizato-customer), [provider](https://github.com/utku54321/servizato-provider), [technician](https://github.com/utku54321/servizato-technician)) through Firebase, so a booking made on one phone shows up live on the others.

## Download

Every push to `main` builds both apps on GitHub (`.github/workflows/build-apps.yml`) and publishes them under **Releases**:

- **Android:** [servizato-customer.apk](https://github.com/utku54321/servizato-customer/releases/latest/download/servizato-customer.apk). Open it on the phone and allow "Install unknown apps" when asked. New builds install over the old one.
- **iPhone:** [servizato-customer.ipa](https://github.com/utku54321/servizato-customer/releases/latest/download/servizato-customer.ipa) (unsigned). Install it from a Windows PC or Mac with [Sideloadly](https://sideloadly.io) and your Apple ID. With a free Apple ID, Apple stops the app after 7 days; install it again to renew. A paid Apple Developer account ($99/year) removes that limit and allows TestFlight.

## Try it

1. Home → pick a category (or search) → add services → Choose provider
2. Pick a provider, date and time slot → Confirm booking
3. Track the booking. Share the OTP with the technician when they arrive
4. Without the partner apps, tap Simulate next update to move the booking forward
5. View invoice and pay → rate the service

## Run it locally

You need Node.js 20 or newer.

```bash
npm install
npx expo run:android   # needs Android Studio
npx expo run:ios       # needs a Mac with Xcode
```

The `android/` and `ios/` folders are generated by `npx expo prebuild` and are not committed; configure the app in `app.json`.

## Project structure

- `index.js` app entry
- `src/App.js` navigation, app state, actions
- `src/screens.js` all screens
- `src/ui.js` design tokens and UI components (cards, buttons, tab bar, …)
- `src/icons.js` line icons (react-native-svg)
- `src/shared.js` link between the three apps (same file in all three repos)
- `src/backend.js` Firebase Firestore sync (same file in all three repos)
- `src/firebase-config.js` Firebase project keys (same file in all three repos)
- `src/data.js` services, providers and bill calculation (same file in all three repos)
- `src/storage.js` on-phone storage; `src/shell.js` startup, back button, toast

## Cloud sync (Firebase)

The apps sync live across phones through Firebase Firestore (project in `src/firebase-config.js`). Without a config they still work, but each phone keeps its own data. Account / More shows the sync status.

`firestore.rules` holds the demo rules: any signed-in (anonymous) app user can read and write. Before real customers, add phone-OTP login and role-based rules (customers see only their bookings, providers only their jobs).
